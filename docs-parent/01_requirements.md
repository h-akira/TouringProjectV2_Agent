# 要件定義

このアプリが「誰の、どんな困りごとを、どう解決するか」と、満たすべき条件を定める。
各ストーリーを満たすための具体的な条件は [詳細要件](04_detailed_requirements.md) に、画面の見た目・文言・配置は [画面モック](mock/index.html) に置く。

## 1. 概要

バイクでツーリングをするライダーが、走行中にスマホに触れず、インカムのボタンと声だけで AI に質問できる Android アプリ。
AI は現在地と進行方向を踏まえ、必要なら自分で調べて、読み上げで答える。

質問と回答は走行ルートとともに記録され、走ったあとに地図の上で「どこで何を聞いたか」を振り返れる。
会話の記録が、そのまま走行記録・走行メモになる。

## 2. 誰のためのアプリか

バイクでツーリングをするライダー。開発者本人と、家族・友人などの身内。一人ひとりが自分の記録を持つ。

| 特徴 | 要件への影響 |
|---|---|
| 走行中は手が使えない | 走行中の操作をスマホの画面に求めない |
| 走行中は画面を見られない | 回答は読み上げる。状態はチラ見で分かるか、音で知らせる |
| ヘルメット内は騒がしい | インカム（イヤホン＋マイク）を前提にする |
| 移動し続けている | 「今どこにいるか・どちらへ向かっているか」が刻々と変わる |
| ナビのアプリを併用している | 応答が終わったらナビの画面に戻す |
| 走ったあとに振り返りたい | 聞いたこと・答え・走った道を、あとから見返せる形で残す |
| 停車中も手袋をしていることが多い | 停車中の操作も、手袋のまま押せる大きさにする |

## 3. 何に困っているか

### 3.1 走行中に、その場所で聞けない

走っていると気になるものが次々に現れるが、走行中はスマホを触れず、確かめる手段がない。

- 「右手に見えるあの山、何ていう山だろう」
- 「この先で給油できるところある？」
- 「この地域って何が有名なんだろう」

> 核心は「調べ物ができない」ことではなく、**その瞬間に、その場所で、聞けない**こと。

### 3.2 聞いたことが、走ったあとに残らない

走行中に聞いて納得したことも、帰るころには「どこで、何を聞いたか」を思い出せない。
走った道と、そこで交わした会話が結びついた形で残っていれば、それ自体が旅の記録になる。

### 3.3 走行の合間の設定や確認が煩わしい

応答のあとに戻るアプリの選択、録音の具合の確認などは停車中に行うが、それらが一つの画面に詰め込まれていると、目的の項目にたどり着きにくい。
とくに戻り先のアプリは候補が多く、一覧が常に目に入るのは邪魔になる。

## 4. コアとなる体験

### 4.1 走行中

```
（停車中に「走行を開始」しておく）

ライダー「（インカムのボタンを押す）右手に見える山は何？（もう一度押す）」
アプリ  「愛鷹山です。富士山の南東にある火山で…」   → 読み上げ後、ナビの画面に戻る

ライダー「へえ。この先で給油できる？」               ← 続けて聞ける
アプリ  「5km先の国道沿いにスタンドがあります」     ← 自分で調べて答える
```

1. 手も目も使わずに聞ける
2. 今いる場所と進行方向を踏まえて答える
3. 続けて質問できる
4. AI が自分で調べて答える（「アプリで検索して」と言わない）
5. 答え終わったら、ナビの画面に戻る

### 4.2 走ったあと

```
（休憩のあいだは「一時停止」し、走り出すときに「再開」する。最後に「走行を終了」する）

地図に今日走ったルートが引かれ、質問した地点にピンが立っている。
ピンをタップすると、そこで聞いたことと AI の答えが読める。
「ここ、また来たいな」とメモを書き足しておく。
```

## 5. ユーザーストーリー

ID は `US-<分類>-<連番>`。連番は詰め直さない（他の文書から ID で参照するため）。使わなくなった番号は「（欠番）」とだけ書く。
優先度は Must（初版に必須）/ Should（初版に入れたい）/ Could（余裕があれば）。

### A：AI との対話

| ID | ストーリー | 優先度 |
|---|---|---|
| US-A-01 | ライダーとして、今いる場所を踏まえて AI に質問したい。その土地のことを知りたいから | Must |
| US-A-02 | ライダーとして、進行方向を踏まえて答えてほしい。「右手に見える山」と聞きたいから | Must |
| US-A-03 | ライダーとして、前の会話を踏まえて続けて質問したい。少し前に聞いた話の続きを聞きたいことはよくあり、一問一答では会話にならないから | Must |
| US-A-04 | ライダーとして、会話の文脈を区切るかどうかは自分で決めたい。区切るのは話題を変えたいと自分が思ったときだけで、それ以外は前の文脈に続けたいから | Must |
| US-A-05 | ライダーとして、AI に自分で調べて答えてほしい。「アプリで検索して」と言われても走行中はできないから | Must |
| US-A-06 | ライダーとして、周辺の施設（給油所・公園・山など）を自分の位置からの向きと距離で知りたい。「右の公園は何」と聞きたいから | Must |
| US-A-07 | ライダーとして、回答を短く、読み上げで聞きやすい形で聞きたい。前置きや記号は走行中の負担になるから | Must |
| US-A-08 | ライダーとして、走行の記録中に停車しているときは、文字でも質問したい。声を出しにくい場所もあるから | Should |

| US-B-03 | ライダーとして、回答を声で聞きたい。走行中は読めないから | Must |

## 6. 機能要件

ユーザーストーリーを、アプリが持つ機能のまとまりに分けたもの。画面との対応は [画面一覧](02_screen_list.md)。

| 機能 | 内容 | 対応する US |
|---|---|---|
| 質問の受付 | インカムのボタンで録音を始め、もう一度の押下か上限の時間で送る。画面のボタンと文字入力でも質問できる。質問を受けるのは走行の記録中だけで、一時停止中・記録していないときは受けず、そのことを声で知らせる | A-08, B-01, B-02 |
| 状況の確定 | 質問ごとに現在地・住所・進行方向・日時を確定し、AI に渡す。調べれば確定するものを AI に推測させない。進行方向は走行のルートから求め、信号待ちなどで止まっているあいだも止まる直前の向きを使う。GPS が正しいかを設定の画面で確かめられる | A-01, A-02 |
| 回答の生成 | 会話の文脈を保ち、必要なら Web 検索・周辺検索を使って答える。読み上げに向く短い文で答える | A-03, A-05, A-06, A-07 |
| 会話の区切り | 会話の文脈は続けるのを基本とする。区切るのは、利用者が区切る操作をしたときと、最後の質問から一定の時間（既定15分。管理者が設定で変える）が経ったときだけ。区切る操作は停車中に押しやすくする | A-03, A-04 |
| 読み上げと復帰 | 回答を読み上げる。ハンズフリーで始めた応答は、回答を待たずに速やかに選んでおいたアプリ（ナビ）へ戻せる。回答待ちと読み上げはナビを表示したまま行う。戻るタイミングは設定で変えられる | B-03, B-04, B-08 |
| 状態の通知 | 録音中・回答待ち・読み上げ中を画面全体で示す。失敗は画面と音で知らせる。どの段階でもやめられる | B-05, B-06, B-07 |
| 走行の記録 | 利用者が開始・終了した走行のルートを記録する。途中で一時停止・再開でき、一時停止中は記録しない。日をまたいでよいが、一時停止せずに連続して記録した時間が最長時間（設定で変えられる）に達すると、終了し忘れとみなして自動で終了する。記録中はアプリが背面にあっても続ける | C-01, C-02, C-07, C-08 |
| 会話の記録 | すべての質問と回答を、日時・場所・進行方向とともに文字で残し、その走行に結びつける | C-03 |
| 通信できないときの質問 | 通信できないときは質問できない（音声を文字にするのも回答もクラウド側で行うため）。録音は捨て、質問しようとした日時・地点だけを記録する | C-09 |
| 音声の保持 | 質問の音声は原則として残さない。録音の確認のためだけに直近の数件を端末に残し、設定の録音の確認でだけ聞ける | C-06, E-03 |
| 記録の保存 | 文字の記録・ルート・メモを端末とクラウドの両方に保存する | C-05, E-05 |
| 振り返り | 記録を走行ごとに見られる。ルートとその走行中の質問・地点メモを（質問・地点メモの表示を切り替え、ルートだけも見られる）、地図と一覧で見る | D-01, D-02, D-03 |
| 記録の編集 | 会話・走行へのメモの追記と編集、走行の名前の変更、会話・走行の削除 | D-04, D-05, D-06 |
| 地点メモ | 日時・位置と結びついたメモを、ホームからすぐ書ける。書けるのは走行の記録中と一時停止中で、その走行に結びつける。文字でも声でも書け、声は文字にするためだけにサーバーへ送る（AI には聞かない）。地図では質問と区別して出す | D-08 |
| 接続の準備 | 接続キーを設定する（保存する前にサーバーへ繋がることを確かめる）。欠けている準備（接続キー・戻り先アプリ）はホームで分かる | E-01 |
| ユーザー | 記録はユーザー名ごとに分けて保存する。接続キーとは関係なく、ユーザー名が同じなら同じ記録になる。別の端末で同じユーザー名を設定すれば記録を引き継げる | C-05, E-06 |
| 設定 | 連続して記録できる最長時間・戻り先アプリ・録音の条件・進行方向の求め方・接続の設定を、項目ごとに分かれた画面で変える | A-02, C-08, E-02, E-04 |
| 録音の確認 | 試し録りと、送った録音（直近の数件）を聞き直し、聞き取られた文と並べて確かめる | E-03 |

## 7. 非機能要件

| 観点 | 要件 |
|---|---|
| 安全 | 走行中に必要な操作は、すべてインカムのボタンだけで完結する。スマホの画面操作を求めない |
| 視認性 | 走行中に画面を見る場合も、一瞬で状態が読み取れる。状態は色だけでも区別できる。走行中に出ることがある画面は、スクロールせずに全体が見える |
| 操作性 | 停車中の操作は手袋のまま押せる大きさにする。押せる領域を重ねない |
| 外観 | 端末のライト／ダークの設定に追従する |
| 応答時間 | 声の質問から読み上げ開始まで、ふだんは30秒以内を目安にする。検索などで長引いても、待っている間は止まっていないことが分かる |
| 記録の完全性 | 文字化された会話は削除の操作をしない限り失わない。通信できないあいだのルートと、質問できなかった地点も端末に記録し、通信できるようになってから送る |
| 音声の保持 | 音声は原則として残さず、確認用に端末に直近の数件のみ。クラウドには長期間残さない |
| 電池 | 走行の記録を数時間続けても、ツーリングに支障のない電池の消費にとどめる |
| プライバシー | 記録はユーザー名ごとに分かれ、他のユーザーの記録と混ざらない。ただし接続キーとユーザー名を知っていれば他人の記録も見られる（身内だけで使うので許容する） |
| 地図 | 国土地理院の地図など、無償で使える地図を用い、出典を表示する |
| 対象端末 | Android のスマホ。インカムは Bluetooth で接続したものを想定する |
| 配布 | 知人に配れればよい。一般公開はしない |
| 費用 | 個人で負担できる範囲に収める |

## 8. やらないこと

| やらないこと | 理由 |
|---|---|
| iOS 対応 | 当面は Android だけで足りる |
| ナビゲーション機能 | 既存のナビのアプリと併用する前提 |
| ウェイクワードでの起動 | 常時マイクを占有する。インカムのボタンで足りる |
| 走行中の画面操作を前提にした機能 | 法律上できない |
| 記録の他人との共有・SNS 投稿 | 自分の振り返りのための記録である |
| 記録の書き出し（ファイル） | 当面はアプリ内で見られれば足りる |
| 記録の文字検索 | 当面は一覧と地図で探せれば足りる |
| 一般公開（ストアでの公開） | 知人に配れれば足りる |
| アカウント登録・パスワードでの認証 | 身内だけで使うので、ユーザー名で記録を分ければ足りる |
| 初めて使うときの準備の案内 | 接続キーとユーザー名は設定の画面で入れられる。欠けている準備はホームで分かる（[adr/0012](../adr/0012-narrow-the-requirements.md)） |
| 走行中にインカムのボタンで声の地点メモを書く | インカムのボタンは質問に使う。声の地点メモは停車中に画面から書く（[adr/0012](../adr/0012-narrow-the-requirements.md)） |
| 一時停止のし忘れの検知 | 終了し忘れは最長時間の自動終了で足りる。一時停止をし忘れても、走行時間が長めに出るだけ（[adr/0012](../adr/0012-narrow-the-requirements.md)） |

## 9. 成功の判定

走行中:

- [ ] インカムのボタンだけで、質問 → 回答の読み上げ → ナビへの復帰が、走りながら通しでできる
- [ ] 現在地と進行方向を踏まえた回答が返る（「右手の〜」が正しく右手を指す）
- [ ] 周辺の施設を、向きと距離を添えて答える
- [ ] 失敗したときに、画面を見なくても音で分かる

走ったあと:

- [ ] 走行を開始してから終了するまでのルートが、一時停止の区間を除いて地図上に引かれている
- [ ] 休憩や宿泊で一時停止し、再開しても、一続きの走行として残る
- [ ] 終了し忘れた走行が、連続して記録した時間が最長時間に達したところで自動的に終了して保存される
- [ ] 質問した地点にピンが立ち、タップすると質問と回答が読める
- [ ] 走行を記録していないとき・一時停止中にインカムのボタンを押すと、質問できないことが声で分かる
- [ ] 通信できず質問できなかった地点が、記録に残る
- [ ] 別の端末で同じユーザー名を設定すると、過去の記録が見られる
- [ ] 同じ接続キーを使っていても、ユーザー名が違えば記録が混ざらない
- [ ] 音声は確認用の直近の数件だけが残り（設定でだけ聞ける）、文字の記録はすべて残っている
