# ユニット間の契約

ユニット（[06_units_definition.md](06_units_definition.md)）どうしの約束。片方だけを変えるともう片方が壊れるものを置く。
ここを変えたら、関係するユニットを両方直す。

項目の名前・型・数値の細部は、各ユニットの設計で API 仕様（OpenAPI）として決め、それを正本にする。ここには、その外側にある約束と、ユニットの間で食い違ってはいけない決まりを書く。

## UC-1 管理規約

### リソースの命名

`<リソースタイプ>-trv2-<env>-<識別子>`

- `env` は `dev` / `prod`。識別子は、単一なら `main`。
- 例: `lambda-trv2-dev-ask`・`dynamodb-trv2-dev-records`・`apigw-trv2-dev-main`
- S3 のバケット名は全世界で一意なので、末尾にアカウント ID を付ける。
- AgentCore のリソース名はハイフンを使えないので、アンダースコアかキャメルケースにする（例: `agentcore_trv2_dev_ask`）。
- 設定値（SSM パラメータ）: `/trv2/<env>/<名前>`。

### リポジトリ

ユニットごとにリポジトリを分け、親のリポジトリで束ねる。CICD だけ非公開にする。

| リポジトリ | 中身 | 公開 |
|---|---|---|
| `TouringProjectV2` | 親（プロジェクト全体の要件・方針・契約。各ユニットを束ねる） | 公開 |
| `TouringProjectV2_App` | App | 公開 |
| `TouringProjectV2_Backend` | Backend | 公開 |
| `TouringProjectV2_Agent` | Agent | 公開 |
| `TouringProjectV2_CICD` | CICD | 非公開 |
親の要件・方針・契約は、各ユニットから参照できるように写す（写しは編集しない）。

## UC-2 リージョンと AI モデル

| | 値 |
|---|---|
| Backend・記録の保存のリージョン | `ap-northeast-1` |
| Agent のリージョン | `us-east-1` |

- Backend から Agent を呼ぶときは、呼び先のリージョンを明示する。
- AI モデルの指定は Agent の設定値として一か所に置く。App と Backend はモデルを知らない（モデルの指定を送らない・持たない）。
- モデルの指定は、Agent のリージョンで使える形（推論プロファイル）で書く。
- モデルの設定値を変えても、App・Backend・Agent の作り直しは要らない（[05_technical_policies.md](05_technical_policies.md) §5）。置き場所は設定値 `/trv2/<env>/agent-model-id`（Agent のリージョン）。Agent は呼ばれるたびに読む（60秒までキャッシュしてよい）。

## UC-3 Agent → Backend: 呼び出し先の受け渡し

| | |
|---|---|
| 受け渡すもの | Agent の実行環境の識別子（ARN） |
| 置き場所 | 設定値 `/trv2/<env>/agent-runtime-arn`。東京（`ap-northeast-1`）に置く |
| 書く側 | Agent のデプロイ |
| 読む側 | Backend のデプロイ（実行時の設定と権限に反映する） |

- デプロイは Agent → Backend の順。
- 識別子が変わったら Backend もデプロイし直す。

## UC-4 App ↔ Backend: 共通の約束

### 認証とユーザー

- すべての呼び出しに接続キーを付ける（死活の確認だけは不要）。接続キーは身内で共通で、アプリのビルドには入れない（利用者が設定で入れる）。
- 記録と質問に関わる呼び出しには、ユーザー名をヘッダ `x-user-name` で付ける（接続キーはヘッダ `x-api-key`）。Backend はユーザー名ごとに記録を分ける。接続キーとユーザー名は独立している。別のユーザー名の記録を求められたら、無いもの（404）として返す。
- ユーザー名は英小文字と数字の3〜20文字。形式に合わなければ Backend は受け付けない。

### 失敗の扱い

- 接続キーが無効なとき（403）は、App はすぐに諦めて利用者に知らせる（繰り返さない）。
- 入力が不正なときは 400 と `{"error": "bad_request", "message": <理由>}` を返す。
- 流量の制限と一時的な通信の失敗は、App が間隔を空けて試し直す。
- 通信できないときに質問は送らない（[04_detailed_requirements.md](04_detailed_requirements.md) US-C-09）。

## UC-5 App ↔ Backend: 質問

### 受け付けと回答の受け取り

項目の名前と型の正本は Backend の `openapi.yaml`。`POST /asks` で受け付け（202）、`GET /asks/{askId}` で取りに行く。

- 質問（音声か文字）は、受け付けた時点で質問の識別子・会話の文脈の識別子・その会話が区切られる時刻を返す。回答はその場では返さない。
- 会話が区切られる時刻は、Backend が受け付けた時刻に設定値 `/trv2/<env>/conversation-reset-minutes`（`ap-northeast-1`。既定15。55以下）の分数を足して求める。App はその時刻を過ぎたら会話の文脈の識別子を捨てる。
- App は質問の識別子で回答を取りに行く。状態は「処理中」「完了」「失敗」の3つ。
- 完了すると、回答の文・読み上げ音声の取り先の一覧・聞き取った文（音声の質問のとき）が返る。聞き取った文は、失敗のときも分かる範囲で返す。
- 読み上げ音声の取り先は、順番つきの一覧で返す。App は順番どおりに続けて鳴らす（1件だけのこともある）。
- 失敗のときは、次の理由のどれかを返す: `no_speech`（聞き取れた文が空）・`transcribe_failed`・`agent_failed`・`tts_failed`。App は自分で判断した `timeout`・`network`・`invalid_key` と合わせて、利用者に知らせる文を選ぶ。
- 取りに行く処理は必ず止まるように作る。最初の10秒は1秒ごと、以後は2秒ごとに取りに行き、120秒で打ち切る。打ち切りや取り消しの後も、Backend の処理は続いてよい。
- App が背面にあるあいだも、取りに行く処理と読み上げは続く（[05_technical_policies.md](05_technical_policies.md) §3）。

### 送るもの

| もの | 内容 |
|---|---|
| 質問 | 音声か文字のどちらか一方。文字は500字まで。音声は PCM（16kHz・モノラル・16bit）の base64 で、0.25〜60秒 |
| 現在地 | 緯度・経度 |
| 方位の材料 | 位置の履歴から選んだ過去の1点と、その時刻（タイムゾーン付き）。方位は Backend が求める。2分より古い点・5m 未満しか離れていない点では方位なしとする |
| 会話の文脈の識別子 | 続けるときだけ。区切るとき（利用者の操作・区切られる時刻の経過）は App が捨て、送らない |
| 回答の音量 | 回答の音声を上げる量（0・3・6・9・12 dB のどれか）。省けば 6dB。Backend は音声を作るときに上げ、質問の記録に残す |
| ユーザー名 | UC-4 |

- 走行の記録中かどうか・どの走行かは、質問の記録を走行に結びつけるために送る。

### 音声

- 録音の形式は、Android が変換なしで出せて、ストリーミングの文字起こしが受け付ける形式にそろえる（PCM・16kHz・モノラル・16bit リトルエンディアン。[adr/0002](../adr/0002-streaming-transcription.md)）。
- 読み上げ音声は、期限付きで取りに行ける場所から App が直接取る。

## UC-6 App ↔ Backend: 文字起こしだけの依頼

地点メモを声で書くときに使う。

- App は音声を送り、Backend は聞き取った文だけを返す。AI は呼ばない。
- 受け付けと受け取りの形は UC-5 と同じ（非同期）。
- 音声は文字にしたら消す。記録には残さない。

## UC-7 App ↔ Backend: 記録の同期

### 対象

走行（名前・開始と終了・一時停止の区間・ルート・走行のメモ・自動終了したか）、質問（文・回答・日時・位置・住所・方位・入力が声か文字か・会話の区切り・メモ）、質問できなかった地点、地点メモ、それぞれの削除。

### 約束

- 記録はユーザー名ごとに分けて保存する。別のユーザー名の記録は返さない。
- 記録の一つひとつは、作った側（App か Backend）が付ける一意の識別子を持つ。同じ識別子のものを何度送っても、記録は1つにまとまる。
- 質問と回答の記録は、Backend が回答を作った時点で保存する。App は質問の識別子で同じ記録を持つ。
- ルート・質問できなかった地点・地点メモ・メモ・名前の変更・削除は、App が作り、通信できるときに送る。通信できないあいだの分は App が溜めておき、後から送る。
- 別の端末で同じユーザー名を設定したときは、App がクラウドの記録を読み込む。
- 端末とクラウドで同じ記録が別々に変えられたときの扱いは、[05_technical_policies.md](05_technical_policies.md) §9 で決め、決まったらここに書く。
- 音声は同期しない。

## UC-8 Backend → Agent: 呼び出し

### 呼び出し

- UC-3 の識別子の実行環境を、リージョンを明示して呼ぶ。
- 会話の文脈の識別子を、AI の実行環境のセッションの識別子としてそのまま渡す。Agent は同じ識別子が来るあいだ文脈を続ける。区切るかどうかは App が決める（UC-5）。
- Agent は回答のあと、文脈からツールの呼び出しと結果を取り除き、質問と回答の文だけを残す。
- 実行環境のセッションのアイドルの時間切れ（60分）は、会話を区切る時間の上限（55分）より長くする。

### 渡すもの

- 呼び出しの本文は JSON の `{"prompt": <文字列>, "location": {"latitude": <数値>, "longitude": <数値>, "headingDegrees": <数値または null>} または null}`。AI への入力（プロンプト）は Backend が組み、Agent はそのまま AI に渡す。入力には次の確定した事実を添える。
  - 現在日時（日本時間・分まで）
  - 会話の最初の質問からの経過時間（一定以上経っているとき）
  - 現在地の座標と住所（住所は町名まで。確定できたときだけ）
  - 進行方位と、ライダーから見た右手・左手の方角（求められたときだけ）
  - 質問の本文（最後に置き、区切りが分かる形にする）
- 周辺検索のツールのために、現在地と進行方位を、プロンプトとは別に数値でも渡す（AI に座標を書き写させないため）。
- Agent は、添えられた事実を推測し直さずにそのまま使う。方位が無いときは方角や左右に触れずに答える。

### 応答

- Agent は SSE（各行 `data: <JSON>`）でイベントを返す。`type` は `text`（回答の断片。前置きを含む）・`tool`（ツールの呼び出しの開始と名前）・`done`・`error` の4つ。
- `done` は最後に1回だけ来る。`answer` は最後のツール呼び出しより後ろの回答だけ（前置きは Agent が除く）。`usage` に入力・出力のトークン数とモデルの呼び出し回数、`modelId` に使ったモデルを入れる。Backend は `answer` を読み上げに使い、`usage` と `modelId` を記録に残す。
- 失敗のときは `done` の代わりに `error` が来る。`code` は `bad_request`（本文が不正）か `agent_failed`（モデル ID が読めない・モデルの失敗・回答が空）。Backend は `agent_failed` として扱う。

## UC-9 CI/CD との関係

- Agent・Backend は、CICD（非公開）がデプロイする。手順は各ユニットのリポジトリに置く。
- App は、版のタグを付けると自動でビルドされ、知人向けのテスト配信に上がる。
- AI モデルの設定値の変更はデプロイを伴わない。管理者が設定値を変える手順は、運用の手順書として持つ。
