# ユニット間の契約

ユニット（[06_units_definition.md](06_units_definition.md)）どうしの約束。片方だけを変えるともう片方が壊れるものを置く。
ここを変えたら、関係するユニットを両方直す。

Android ↔ Backend の項目の名前・型・数値の細部は [07a_openapi.yaml](07a_openapi.yaml)、記録の種類と関係は [07b_datamodel.md](07b_datamodel.md) を正本にする。ここには、その外側にある約束と、ユニットの間で食い違ってはいけない決まりを書く。

## UC-1 管理規約

### リソースの命名

`<リソースタイプ>-trv2-<env>-<識別子>`

- `env` は `dev` / `prod`。識別子は、単一なら `main`。
- 例: `lambda-trv2-dev-ask`・`dynamodb-trv2-dev-records`・`apigw-trv2-dev-main`
- S3 のバケット名は全世界で一意なので、末尾にアカウント ID を付ける。
- AgentCore のリソース名はハイフンを使えないので、アンダースコアかキャメルケースにする（例: `agentcore_trv2_dev_ask`）。
- 設定値（SSM パラメータ）: `/trv2/<env>/<名前>`。

### リポジトリ

ユニットごとにリポジトリを分け、親のリポジトリで束ねる。CICD だけ非公開にする。

| リポジトリ | 中身 | 公開 |
|---|---|---|
| `TouringProjectV2` | 親（プロジェクト全体の要件・方針・契約。各ユニットを束ねる） | 公開 |
| `TouringProjectV2_Android` | Android | 公開 |
| `TouringProjectV2_Backend` | Backend | 公開 |
| `TouringProjectV2_Agent` | Agent | 公開 |
| `TouringProjectV2_CICD` | CICD | 非公開 |

親の `docs/`（要件・方針・契約・基本設計。`07a_openapi.yaml` を含む）は、各ユニットの `docs-parent/` に写す（`scripts/sync-docs.sh`。写しは編集しない）。Backend のテストは、写しの `07a_openapi.yaml` が実装と合うことを確かめる。

## UC-2 リージョンと AI モデル

| | 値 |
|---|---|
| Backend・記録の保存のリージョン | `ap-northeast-1` |
| Agent のリージョン | `us-east-1` |

- Backend から Agent を呼ぶときは、呼び先のリージョンを明示する。
- AI モデルの指定は Agent の設定値として一か所に置く。Android と Backend はモデルを知らない（モデルの指定を送らない・持たない）。
- モデルの指定は、Agent のリージョンで使える形（推論プロファイル）で書く。
- モデルの設定値を変えても、Android・Backend・Agent の作り直しは要らない（[05_technical_policies.md](05_technical_policies.md) §5）。置き場所は設定値 `/trv2/<env>/agent-model-id`（Agent のリージョン）。Agent は呼ばれるたびに読む（60秒までキャッシュしてよい）。

## UC-3 Agent → Backend: 呼び出し先の受け渡し

| | |
|---|---|
| 受け渡すもの | Agent の実行環境の識別子（ARN） |
| 置き場所 | 設定値 `/trv2/<env>/agent-runtime-arn`。東京（`ap-northeast-1`）に置く |
| 書く側 | Agent のデプロイ |
| 読む側 | Backend のデプロイ（実行時の設定と権限に反映する） |

- デプロイは Agent → Backend の順。
- 識別子が変わったら Backend もデプロイし直す。

## UC-4 Android ↔ Backend: 共通の約束

### 認証とユーザー

- すべての呼び出しに接続キーを付ける（死活の確認だけは不要）。接続キーは身内で共通で、アプリのビルドには入れない（利用者が設定で入れる）。
- 記録と質問に関わる呼び出しには、ユーザー名をヘッダ `x-user-name` で付ける（接続キーはヘッダ `x-api-key`）。Backend はユーザー名ごとに記録を分ける。接続キーとユーザー名は独立している。別のユーザー名の記録を求められたら、無いもの（404）として返す。
- ユーザー名は英小文字と数字の3〜20文字。形式に合わなければ Backend は受け付けない。

### 失敗の扱い

- 接続キーが無効なとき（403）は、Android はすぐに諦めて利用者に知らせる（繰り返さない）。
- 入力が不正なときは 400 と `{"error": "bad_request", "message": <理由>}` を返す。
- 流量の制限と一時的な通信の失敗（5xx を含む）は、Android が間隔を空けて試し直す。書き込みと削除は、何度送っても同じ結果になる。
- 質問を受け付けたが処理に回せなかったときは、記録を残さずに 503 を返す。Android は通信の失敗と同じに扱う。
- 通信できないときに質問は送らない。Android は「質問できなかった地点」として残し、後で送る（[04_detailed_requirements.md](04_detailed_requirements.md) US-C-09、UC-7）。
- 文字数の上限は、前後の空白を落としたあとの Unicode のコードポイントの数で数える。

## UC-5 Android ↔ Backend: 質問

### 受け付けと回答の受け取り

項目の名前と型の正本は [07a_openapi.yaml](07a_openapi.yaml)。`POST /asks` で受け付け（202）、`GET /asks/{askId}` で取りに行く。

- 質問（音声か文字）は、受け付けた時点で質問の識別子・会話の文脈の識別子・その会話が区切られる時刻を返す。回答はその場では返さない。
- 会話が区切られる時刻は、Backend が受け付けた時刻に設定値 `/trv2/<env>/conversation-reset-minutes`（`ap-northeast-1`。既定15。55以下）の分数を足して求める。Android はその時刻を過ぎたら会話の文脈の識別子を捨てる。
- Android は質問の識別子で回答を取りに行く。状態は「処理中」「完了」「失敗」の3つ。質問できなかった地点（UC-7）を問い合わせたときだけ「質問できなかった」が返る（処理されないので、回答は来ない）。
- 完了すると、回答の文・読み上げ音声の取り先の一覧・聞き取った文（音声の質問のとき）が返る。聞き取った文は、失敗のときも分かる範囲で返す。
- 読み上げ音声の取り先は、順番つきの一覧で返す。Android は順番どおりに続けて鳴らす（1件だけのこともある）。
- 失敗のときは、次の理由のどれかを返す: `no_speech`（聞き取れた文が空）・`transcribe_failed`・`agent_failed`・`tts_failed`。Android は自分で判断した `timeout`・`network`・`invalid_key` と合わせて、利用者に知らせる文を選ぶ。
- 取りに行く処理は必ず止まるように作る。最初の10秒は1秒ごと、以後は2秒ごとに取りに行き、120秒で打ち切る。打ち切りや取り消しの後も、Backend の処理は続いてよい。
- Android が背面にあるあいだも、取りに行く処理と読み上げは続く（[05_technical_policies.md](05_technical_policies.md) §3）。
- 結果には、受け付けた日時（UTC）・質問した地点の住所（確定できなかったら無し）・進行方位（方位なしなら無し）も入る。Android はこれを端末の記録に残す（質問の記録は Backend が作るので、Android から送り返さない。UC-7）。

### 送るもの

| もの | 内容 |
|---|---|
| 質問 | 音声か文字のどちらか一方。文字は500字まで。音声は PCM（16kHz・モノラル・16bit）の base64（改行と空白は無視する）で、0.25〜60秒 |
| 現在地 | 緯度・経度 |
| 進行方位 | 真北から時計回りの度数（0以上360未満）。方位なしなら無し。Android が走行のルートから求める（[05_technical_policies.md](05_technical_policies.md) §3・[adr/0013](../adr/0013-heading-on-android-held-while-stopped.md)）。Backend は0以上360未満の数でなければ方位なしとして扱う |
| 方位の材料（古い形） | 位置の履歴から選んだ過去の1点と、その時刻（タイムゾーン付き）。端末に残った古い未送信のために受ける。進行方位が無いときだけ、Backend がこれから方位を求める（2分より古い点・5m 未満しか離れていない点では方位なし） |
| 会話の文脈の識別子 | 続けるときだけ。区切るとき（利用者の操作・区切られる時刻の経過）は Android が捨て、送らない |
| 回答の音量 | 回答の音声を上げる量（0・3・6 dB のどれか）。省けば 6dB（最大）。Backend は音声を作るときに上げ、質問の記録に残す |
| ユーザー名 | UC-4 |

- 質問は走行の記録中だけ受けるので（[adr/0008](../adr/0008-ask-only-while-recording.md)）、アプリは質問にいつもその走行の識別子を添える。API の上では識別子を省ける。Backend は質問の記録に残す。

### 音声

- 録音の形式は、Android が変換なしで出せて、ストリーミングの文字起こしが受け付ける形式にそろえる（PCM・16kHz・モノラル・16bit リトルエンディアン。[adr/0002](../adr/0002-streaming-transcription.md)）。
- 読み上げ音声は、期限付きで取りに行ける場所から Android が直接取る。

## UC-6 Android ↔ Backend: 文字起こしだけの依頼

地点メモを声で書くときに使う。

- Android は音声を送り、Backend は聞き取った文だけを返す。AI は呼ばない。
- 受け付けと受け取りの形は UC-5 と同じ（非同期）。項目の名前と型の正本は [07a_openapi.yaml](07a_openapi.yaml)。`POST /transcriptions` で受け付け（202）、`GET /transcriptions/{transcriptionId}` で取りに行く。
- 音声の形と長さは、質問の音声と同じ（UC-5「送るもの」）。
- 状態は「処理中」「完了」「失敗」の3つ。完了なら聞き取った文、失敗なら理由（`no_speech`（聞き取れた文が空）・`transcribe_failed`）を返す。取りに行く間隔と打ち切りは UC-5 と同じ。
- 音声は文字にしたら消す。記録には残さない。結果は受け付けてから1日で消える。

## UC-7 Android ↔ Backend: 記録の同期

### 対象

走行（名前・開始と終了・一時停止の区間・ルート・走行のメモ・自動終了したか）、質問（文・回答・日時・位置・住所・方位・入力が声か文字か・会話の区切り・メモ）、質問できなかった地点、地点メモ、それぞれの削除。

### 約束

- 記録はユーザー名ごとに分けて保存する。別のユーザー名の記録は返さない。
- 記録の一つひとつは、作った側（Android か Backend）が付ける一意の識別子を持つ。同じ識別子のものを何度送っても、記録は1つにまとまる。
- 質問と回答の記録は、Backend が回答を作った時点で保存する。Android は質問の識別子で同じ記録を持つ。
- ルート・質問できなかった地点・地点メモ・メモ・名前の変更・削除は、Android が作り、通信できるときに送る。通信できないあいだの分は Android が溜めておき、後から送る。
- 別の端末や入れ直したあとに同じユーザー名を設定したとき（ユーザー名を変えるとき）と、利用者が読み直すときに、Android がクラウドの記録を読み込む（下の「読み込みと突き合わせ」）。
- 音声は同期しない。

### 走行の送り方

- 走行のメタ情報（名前・状態・記録した区間・自動終了したか・走行のメモ・Android が変更した時刻）は、変わるたびに最新の全体を置く。Backend は、Android が変更した時刻が保存済みのものより新しいときだけ上書きし、古ければ何もせずに受け取ったと返す。
- ルートの点は、300点までのかたまりに番号を付けて置く。同じ番号は丸ごと上書きする。かたまりは走行のメタ情報より先に届いてもよい。
- かたまりの番号は、Android が走行の点を記録した順に300点ずつ区切った順番（0から）。記録中は満ちたかたまりだけを置き、一時停止と終了では満ちていない最後のかたまりも置く。あとで点が増えたら、同じ番号で置き直す。
- 入力が不正（400）なものは送り直さない。

### 書き足しと削除の送り方

- 会話のメモは質問ごとに、地点メモは1件ごとに、最新の全体を置く。どちらも、Android が変更した時刻が保存済みのものより新しいときだけ書き、古ければ何もせずに受け取ったと返す。会話のメモは、Backend に無い質問には置けない（無いものとして返す）。
- 地点メモの住所（町名まで）は Backend が最初に受けたときに、質問と同じ求め方で決めて返す。進行方位は Android が送ったものを最初に受けたときに記録して返す。どちらもあとから置き直しても変えない（住所を確定できなかったときは、次に置いたときに求め直す）。地点メモは、その走行のメタ情報より先に届いてもよい。
- 削除は記録ごとに送る。Backend は先に削除の跡を残してから消す。走行を消すと、そのルート・地点メモ・質問も消え、地点メモと質問にも跡が残る。何度送っても、無いものを消しても、同じ結果になる。
- 跡のある記録と、跡のある走行の下の記録（ルート・地点メモ）への書き込みは、書かずに「消されている」（410）と返す。Android は送れたものと同じに扱い、送り直さない（[adr/0009](../adr/0009-keep-deletion-marks-in-the-cloud.md)）。
- 跡には期限が無い。読み込みで、端末をまたいで削除を伝えるのに使う。

### 質問できなかった地点の送り方

- 質問が Backend に届かなかったとき（録音を終えた時点で通信できない・受け付けが通信の失敗に終わった）は、Android がその日時・位置・進行方位・走行を、自分で作った質問の識別子で残し、通信できるときに置く。
- Backend は「質問できなかった」状態の質問として置き、位置・住所・方位を地点メモと同じく最初に受けたときに決めて返す（方位は Android が送ったもの）。あとの版で位置を変えても消しても、最初の値のまま。Android が変更した時刻が新しいときだけ書く。会話のメモは残す。
- メモと削除は、ほかの質問と同じ送り方。Backend が受け付けた質問と同じ識別子なら、書かずに「重なっている」（409）と返す。

### 読み込みと突き合わせ

- Android はユーザーの記録（走行・ルート・地点メモ・質問・質問できなかった地点・削除の跡）を、ページ送りで最後まで読む。Backend は記録の識別子の順に強い一貫性で返す。項目の名前と型の正本は [07a_openapi.yaml](07a_openapi.yaml)（`GET /records`）。
- 同じ記録が端末とクラウドの両方にあれば、Android が変更した時刻が新しいほうを残す。クラウドに削除の跡があれば、端末から消す。端末にだけある未送信の記録は残して送る（[adr/0010](../adr/0010-read-the-cloud-only-when-taking-over.md)）。
- 読み込みは引き継ぎのとき（ユーザー名を変えるとき）と利用者が読み直すときだけ。2台を同時に使っても、一方の変更はもう一方で読み直すまで届かない。
- 比べる時刻は、走行はメタ情報の `updatedAt`、地点メモと質問できなかった地点は `updatedAt`、会話のメモは `memoUpdatedAt`。Backend が受け付けた質問は、中身（文字起こし・回答・結果）をクラウドの値で入れ、メモだけを比べる。ルートは走行ごとに点の多いほうを残す（点は足していくだけで減らない）。
- 端末にまだ送っていない削除の印がある記録は、クラウドの写しを入れない。走行の無い記録は入れない。
- 記録中・一時停止中のままクラウドにある走行は、最後の点の時刻で終えた走行として入れ、その「終えた」版を送り直す。結果の出ていない質問（`processing`）は、時間内に答えが届かなかった失敗として入れる。
- 入れた記録は送り済みにし、送り返さない。

## UC-8 Backend → Agent: 呼び出し

### 呼び出し

- UC-3 の識別子の実行環境を、リージョンを明示して呼ぶ。
- AI の実行環境のセッションの識別子には、ユーザー名と会話の文脈の識別子から作った値（SHA-256 の16進）を渡す。同じ会話の識別子を別のユーザー名で送っても、別のセッションになる。Agent は同じ識別子が来るあいだ文脈を続ける。区切るかどうかは Android が決める（UC-5）。
- Agent は回答のあと、文脈からツールの呼び出しと結果を取り除き、質問と回答の文だけを残す。
- 実行環境のセッションのアイドルの時間切れ（60分）は、会話を区切る時間の上限（55分）より長くする。

### 渡すもの

- 呼び出しの本文は JSON の `{"prompt": <文字列>, "location": {"latitude": <数値>, "longitude": <数値>, "headingDegrees": <数値または null>} または null}`。AI への入力（プロンプト）は Backend が組み、Agent はそのまま AI に渡す。入力には次の確定した事実を添える。
  - 現在日時（日本時間・分まで）
  - 会話の最初の質問からの経過時間（一定以上経っているとき）
  - 現在地の座標と住所（住所は町名まで。確定できたときだけ）
  - 進行方位と、ライダーから見た右手・左手の方角（求められたときだけ）
  - 質問の本文（最後に置き、区切りが分かる形にする）
- 周辺検索のツールのために、現在地と進行方位を、プロンプトとは別に数値でも渡す（AI に座標を書き写させないため）。
- Agent は、添えられた事実を推測し直さずにそのまま使う。方位が無いときは方角や左右に触れずに答える。

### 応答

- Agent は SSE（各行 `data: <JSON>`）でイベントを返す。`type` は `text`（回答の断片。前置きを含む）・`tool`（ツールの呼び出しの開始と名前）・`done`・`error` の4つ。
- `done` は最後に1回だけ来る。`answer` は最後のツール呼び出しより後ろの回答だけ（前置きは Agent が除く）。`usage` に入力・出力のトークン数とモデルの呼び出し回数、`modelId` に使ったモデルを入れる。Backend は `answer` を読み上げに使い、`usage` と `modelId` を記録に残す。
- モデルが周回の上限（ツールの呼び出しを含む）に達して回答の文が無いときは、`done` の `answer` に決まった文（「調べきれませんでした。」）を入れて返す（`stopReason` は上限の名前）。モデルの出力のトークンの上限で止まったときは、最後のツールの呼び出しより後ろの途中までの文を `answer` にし、文が無ければ同じ決まった文にする（`stopReason` は `max_tokens`）。失敗の音ではなく、調べきれなかったことを読み上げるため（US-A-05.003）。
- 失敗のときは `done` の代わりに `error` が来る。`code` は `bad_request`（本文が不正）か `agent_failed`（モデル ID が読めない・モデルの失敗・上限でないのに回答が空）。Backend は `agent_failed` として扱う。

## UC-9 CI/CD との関係

- Agent・Backend は、CICD（非公開）がデプロイする。この仕組みが無いあいだは、開発者が各ユニットの README の手順でデプロイする。
- Android は、版のタグを付けると自動でビルドされ、知人向けのテスト配信に上がる。この仕組みが無いあいだは、開発者の Mac で走行用のビルドを作って端末に入れる（手順は Android の README）。
- AI モデルの設定値の変更はデプロイを伴わない。管理者が設定値を変える手順は、運用の手順書として持つ。
